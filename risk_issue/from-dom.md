# fromDom (DOM → VNode) 리스크·이슈

관련 코드: `src/core/html-to-vnode/fromDom.ts` · 기획서: [docs/from-dom.md](../docs/from-dom.md)

## FD-01

**Patch 외의 DOM 변경으로 1:1 대응 깨짐** · 높음 · 예상

- **현상:** 정규화 마운트 후 실제 영역 DOM과 VNode는 1:1로 대응한다. 그런데 브라우저 확장, 개발자 도구 편집, 다른 스크립트가 실제 영역에 공백 텍스트나 노드를 넣으면 대응이 깨진다. 인접한 텍스트 노드가 둘로 나뉘는 경우도 마찬가지다. VNode에서는 하나로 합쳐지지만 DOM 경로는 둘이 된다.
- **영향:** 경로 기반 Patch가 엉뚱한 노드를 수정한다. 오류 없이 화면이 조용히 틀어진다.
- **대응안:** 실제 영역에 쓰는 코드는 Patch와 mount뿐이라는 규칙을 둔다. Patch 전에 대상 노드의 `localName`이 VNode `tag`와 같은지 확인하고, 다르면 전체 다시 mount로 복구한다.

## FD-02

**화면 상태가 VNode에 없음** · 중간 · 예상

- **현상:** VNode는 마크업 속성만 담는다. 사용자가 입력한 `input.value`, `checked`, `select` 선택값, `<details open>` 토글, 스크롤 위치는 읽지 않는다.
- **영향:** 해당 요소를 REPLACE하는 Patch나 뒤로가기 후 mount를 하면 사용자가 입력한 상태가 사라진다.
- **대응안:** 기획서대로 property 동기화는 Patch 단계에서 처리한다. 의도된 동작인지, 보존해야 하는지 Patch 기획에서 정한다.

## FD-03

**실제 영역 샘플에도 보안 필터 적용** · 중간 · 기획 리스크

- **현상:** 두 경로가 같은 `convertChildren`을 쓰므로 개발자가 직접 쓴 샘플의 `onclick` 등도 제거된다. 정규화 마운트 후에는 DOM에서도 사라진다.
- **영향:** 샘플에 인라인 이벤트로 동작을 붙여두면 로드 직후 동작하지 않는다.
- **대응:** 기획서 현재 안(적용) 유지. 샘플 동작은 `addEventListener`로 컨테이너에 위임해서 붙인다.

## FD-04

**최상위 `<tr>`, `<td>` 샘플 소실** · 낮음 · 기획 리스크

- **현상:** `fromHtml`이 template 안에서 파싱할 때 문맥이 없는 최상위 `<tr>`, `<td>`는 버려진다.
- **대응:** 샘플은 `<table>`로 감싸서 작성한다.

## FD-05

**Shadow DOM·커스텀 요소** · 낮음 · 예상

- **현상:** `childNodes`만 순회하므로 Shadow DOM 내부는 표현되지 않는다. 커스텀 요소는 일반 태그로 다뤄진다.
- **영향:** 샘플에 웹 컴포넌트를 쓰면 화면과 VNode가 다르다.
- **대응:** 샘플에서 웹 컴포넌트를 쓰지 않는다.
