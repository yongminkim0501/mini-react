# PR 제출 · v0.1

1. 최신 마일스톤 이슈와 관련 이슈를 다시 읽고, 배정·ready·완료 조건·변경 전제가 유효한지 확인한다. 전제가 바뀌었으면 중지하고 자기 사람 담당자에게 알린다.
2. `git diff --name-only <기준커밋>...HEAD`의 실제 파일을 `.github/areas.yml`에 대응시킨다. 예상 영역과 다르면 PR 본문에 추가 영역과 이유를 기록하고 그 영역의 사람 담당자를 @멘션한다. shared는 전원에게 알린다. 담당자가 비어 있거나 지도 밖 경로이면 자기 담당자에게 알리고 미확인으로 기록한다.
3. 착수 이후 등록된 동일 영역 이슈와 현재 열린 PR을 저장소 전체에서 조회한다. 목록을 페이지 누락 없이 읽고, 겹침 링크와 사람 담당자 @멘션을 기록한다. 착수 기록이 없으면 임의 시각을 만들지 말고 전체 열린 작업을 확인했다고 명시한다.
4. `.github/pull_request_template.md`에 맞춰 `Refs #번호`, 완료 조건 각각의 검증 명령·실제 결과·증거·검증 대상 전체 커밋 SHA, 호환성 영향을 적는다. 실패·미실행·일부 충족을 통과로 표시하지 않는다. 별개 문제는 별도 이슈로 등록한다.
5. 미정인 세부 사항은 `가정` 목록으로 명시한다. 사람이 결과물을 검토하기 전에는 원격에 반영하지 않는다. 검토 전에는 로컬 본문과 diff를 준비하고, 이미 검토·제출 지시가 있으면 그 범위에서 진행한다. 이슈와 같은 마일스톤을 PR에도 지정한다. 본문은 파일로 저장해 `gh pr create --body-file <파일> --milestone "<이름>"`에 전달한다.
6. 원격 PR이 있으면 actions/labeler 결과와 실제 영역이 일치하는지 확인한다. 워크플로가 기준 브랜치에 없거나 아직 실행되지 않았으면 자동 부착 완료로 보고하지 않는다.

PR URL 또는 로컬 초안 경로, 완료·미충족 조건, 추가 영역과 필요한 사람 확인을 보고한다. 승인·병합·이슈 종료·담당 변경은 하지 않는다.
